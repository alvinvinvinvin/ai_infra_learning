# 为什么用 K3s 而不是 K8s？—— 一个学习者的视角

## 核心结论

**你装 K3s 是对的，完全没有装错，而且反而因此学到了更多东西。**

---

## 1. 你学到的绝大部分东西，都是 K8s 的通用知识

你之前几天学到的所有核心概念，**全部**是原生 Kubernetes 标准，K3s 和标准 K8s 完全一样：

### ✅ 你已学过的内容（100% 通用）

| 类别 | 内容 |
|------|------|
| **工作负载** | Pod / Deployment / Service / Ingress |
| **配置管理** | ConfigMap / Secret |
| **更新策略** | 滚动更新 / 回滚 |
| **自动扩缩容** | HPA（水平自动扩缩容） |
| **存储** | PV / PVC |
| **包管理** | Helm |
| **安全** | RBAC / SecurityContext / PodSecurity Standards |
| **网络** | Service Mesh（Istio） |
| **资源管理** | ResourceQuota / LimitRange |

你学到的这些，在任何标准 Kubernetes 集群上 **100% 通用**。

**你并没有因为用 K3s 而学到"缩水版"的东西。**

---

## 2. K3s 和 K8s 的区别在哪里？

真正有区别的地方是这些：

| 方面 | 标准 K8s | K3s | 对你的影响 |
|------|----------|-----|-----------|
| **控制平面组件** | 多个独立进程 | 单二进制 | 运维层面不同，但 API 完全一样 |
| **存储后端** | etcd | SQLite（默认） | 你还没学到 etcd 运维，这是以后的事 |
| **默认 CNI** | 通常是 Calico | Flannel | **这是你今天遇到的唯一区别** |
| **安装方式** | kubeadm / 托管服务 | 一条命令 | 运维层面不同，但 API 完全一样 |

**你在 K3s 上遇到的唯一"限制"，就是今天 NetworkPolicy 需要额外安装 Calico。**

这不是 K3s 的缺陷，而是它为了轻量做了合理取舍。

---

## 3. 你反而学到了更多东西

如果你一开始就装了托管的 K8s（如 EKS/GKE）或标准 K8s：

- ✅ 你可能会直接上手应用部署，很顺利
- ❌ 但你永远不会知道以下这些：

| 问题 | 标准 K8s 用户可能永远不知道 | 你在 K3s 上被迫学到了 |
|------|---------------------------|----------------------|
| CNI 是什么？ | ❌ 可能不知道 | ✅ 知道了 CNI 是网络插件 |
| 为什么 NetworkPolicy 需要 CNI 支持？ | ❌ 可能不知道 | ✅ 知道了 K8s 只定义规范，执行靠 CNI |
| Flannel 和 Calico 有什么区别？ | ❌ 可能不知道 | ✅ 知道了 Flannel 只管连通，Calico 带防火墙 |
| K8s 和 K3s 有什么区别？ | ❌ 可能不知道 | ✅ 知道了轻量版和完整版的取舍 |

**K3s 让你看到了 K8s 的"内部构造"，而标准 K8s 可能让你停留在"用户视角"。**

---

## 4. 什么时候需要换成标准 K8s？

| 阶段 | 建议 |
|------|------|
| **学习阶段（你现在）** | K3s 完全够用，甚至更好 —— 轻量、快速、底层可见 |
| **生产环境大规模集群** | 可以考虑标准 K8s 或 EKS/GKE |
| **需要 etcd 运维经验** | 以后专门学，不冲突 |
| **需要高级网络策略** | 在 K3s 上装 Calico 就行，5 分钟的事 |

你今天第 1 天用 K3s，学到第 12 天才发现 CNI 这个差异点，这本身就是非常正常的学习路径。

---

## 5. 类比理解

| 场景 | 类比 |
|------|------|
| **标准 K8s** | 一台预装好所有软件的企业级服务器 |
| **K3s** | 一台轻量笔记本电脑，需要自己装一些驱动 |

用轻量笔记本电脑学 Linux：
- 你会遇到驱动问题 → 学会了装驱动
- 你会遇到内存限制 → 学会了优化配置
- 你会遇到网络配置 → 学会了网络原理

**这些经验，在企业的标准服务器上反而学不到。**

---

## 6. 一句话总结

> **你没有装错。你只是用了一台"轻量笔记本电脑"来学习 Kubernetes——能学的内容一样多，甚至因为硬件限制，你反而学会了更多底层知识。**
